# Contributing to SecureLine

## Development Process

1. Fork the repository
2. Create a feature branch
3. Make your changes
4. Run tests
5. Submit a pull request

## Code Style

- Java: follow Google Java Style Guide
- XML: 4-space indentation
- YAML: 2-space indentation

## Security Guidelines

- Never commit secrets or keys
- Never use insecure algorithms
- Always use SecureRandom for cryptographic operations
- Run all tests before submitting

## Review Process

All pull requests require at least one review from a maintainer.
Security-related changes require two reviews.
